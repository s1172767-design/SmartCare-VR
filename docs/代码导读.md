# 代码导读：30 分钟看懂这个项目

这份文档写给「前端不太熟、但需要能讲清楚代码」的人。
读完你应该能回答三个问题：**数据从哪来、页面怎么变、出错去哪查。**

---

## 0. 先建立三张地图

### 地图一：文件谁负责什么

```
你看到的页面
├── 骨架   frontend/index.html     页面有哪些区域（section / div / button）
├── 皮肤   frontend/styles.css     颜色、间距、手机端怎么变
├── 行为   frontend/app.js         取数据、渲染、判题、提交成绩
└── 3D     frontend/scene.js       Three.js 房间、相机、移动、点击线索

数据从哪来
├── 路由   backend/main.py         6 个接口 + 托管前端
├── 题目   backend/data.py         4 个情景、5 门课程
├── 存储   backend/db.py           SQLite 建表与读写
└── 对话   backend/ai.py           调大模型 / 失败时用预设回复
```

**记住一句话**：前端只负责「好看和好用」，后端只负责「有什么、算多少、存哪里」。

### 地图二：一次答题，发生了哪些请求

```
浏览器                           FastAPI
  │  GET  /api/scenarios  ──────>  返回 4 个情景（不含答案）
  │  GET  /api/courses    ──────>  返回 5 门课程
  │  GET  /api/profile    ──────>  返回成绩与雷达图数值
  │
  │  点某个选项
  │  POST /api/scenarios/fall/check ──> 后端判对错，返回解释
  │
  │  答完 4 题
  │  POST /api/attempts   ──────>  后端算分、写库、返回记录
  │  GET  /api/profile    ──────>  刷新面板与雷达图
```

打开浏览器 F12 → **Network**，把上面每一条都对一遍，你就理解了整个架构。

### 地图三：数据存在哪

| 数据 | 存在哪 | 刷新会丢吗 | 换设备能看到吗 |
|---|---|---|---|
| 题库、课程 | Python 文件 | 不会 | 会 |
| 答题进度（第几题） | 浏览器内存 `progress` | **会丢** | 不会 |
| 已完成成绩 | SQLite `smartcare.db` | 不会 | 会*（同一 learner_id） |
| 学员身份 | 浏览器 `localStorage` | 不会 | 不会 |
| 对话上下文 | 浏览器内存 `chatHistory` | 会丢 | 不会 |

## 1. 后端：四个文件，从哪读起

### 1.1 `backend/main.py` —— 先看路由

每个 `@app.get` / `@app.post` 就是一条「网址 → 函数」的映射：

```python
@app.get("/api/scenarios")          # 浏览器访问这个网址时
def list_scenarios():               # 执行这个函数
    return {...}                    # 返回的 dict 自动变成 JSON
```

读代码时按这个顺序看四个函数：

1. `list_scenarios()` —— 返回题库，注意它调用 `public_scenario()` **删掉了答案**
2. `check_answer()` —— 判题，正确答案只在这里出现
3. `create_attempt()` —— 算分并入库
4. `get_profile()` —— 把历史记录折算成六维数值

最后一行 `app.mount("/", StaticFiles(...))` 是「顺便把前端文件发出去」，
**因为接口和页面在同一个域名下，所以完全不用处理跨域（CORS）**。

### 1.2 `backend/data.py` —— 数据长什么样

一个情景就是一个字典：

```python
"fall": {
    "title": "老人跌倒处理",
    "elderPos": [390, 320],        # 2D 地图上的坐标
    "hotspots": [...],             # 3 个可点击线索
    "steps": [                     # 4 道题
        {"title": "...", "choices": [...], "correct": 1, "feedback": "..."}
    ]
}
```

改题目只改这个文件，前端一行都不用动 —— 这就是「数据与逻辑分离」。

### 1.3 `backend/db.py` —— 只有一张表

```sql
CREATE TABLE attempts (
  id, learner_id, scenario, score, correct, total, created_at
);
```

看三个函数就够：`init_db()` 建表、`insert_attempt()` 插入、`list_attempts()` 查询。
注意每个函数都是「开连接 → 执行 → 关闭」，这是短连接写法，简单且不会串数据。

### 1.4 `backend/ai.py` —— 学会「优雅降级」

这是最值得学的一个文件。它做三件事：

```python
if not is_configured():                  # 没配 Key
    return 规则回复                        # → 用预设台词，页面照常能用
try:
    return 调模型(...)                     # 配了 Key
except (超时, 网络错误, 格式错误):
    return 规则回复                        # → 演示现场绝不白屏
```

**核心思想：外部依赖一定会失败，失败时要有体面的退路。**
答辩被问到「网络断了怎么办」，你可以直接翻到这段。

## 2. 前端：只需要懂 5 个动作

`app.js` 全文 700 多行，但只反复用这 5 个动作：

| 动作 | 代码 | 在项目里的例子 |
|---|---|---|
| 找元素 | `document.querySelector("#id")` | `$("#missionScore")` |
| 改内容 | `element.textContent = "..."` | 改分数、改老人台词 |
| 听事件 | `element.addEventListener("click", fn)` | 点选项、点情景标签 |
| 发请求 | `await fetch("/api/...")` | 取题库、提交成绩 |
| 存本地 | `localStorage.setItem` | 记住 learner_id |

**没有框架，没有编译，浏览器拿到什么就跑什么。** 这就是为什么它不需要 Node.js。

### 两个必须理解的关键词

```js
async function loadScenarios() {
  const data = await fetch("/api/scenarios");   // await：等网络回来再往下走
  scenarios  = await data.json();               // .json()：把 JSON 文本变成对象
}
```

- `async` 表示「这个函数里会有等待」
- `await` 表示「等这件事做完，再执行下一行」
- 没有 `await`，你会拿到一个 Promise（一个「还没好」的占位符），后面全乱

## 3. 跟着一次答题走完全流程

假设你点开「老人跌倒处理」，选了第 1 题的第 2 个选项：

```
① 点击        index.html 的 <button data-choice="1">
              ↓
② app.js      selectChoice(1)            ← 找到这个函数
              ↓
③ app.js      postJSON("/api/scenarios/fall/check", {step:0, choice:1})
              ↓  HTTP
④ main.py     check_answer()              ← 后端比对 correct
              ↓  {"correct": true, "answer": 1, "feedback": "..."}
⑤ app.js      state.results[0] = 结果；state.score = 1
              ↓
⑥ app.js      renderMission()             ← 重新生成右边任务面板的 HTML
              ↓
⑦ 浏览器      绿框标出正确项 + 显示解释
```

答完第 4 题时，多一步：

```
⑧ app.js      recordCompletion() → POST /api/attempts（只提交选项，分数由后端算）
⑨ main.py     create_attempt() → 算分 → db.insert_attempt() 写库
⑩ app.js      loadProfile() → GET /api/profile → renderAssessment() 重画雷达图
```

**把这条链走通，你就掌握了整个项目 80% 的逻辑。**

做完这五个，你就能独立改这个项目了。

**目的**：确认「数据在后端」这件事是真的。

### 练习 2：加一道题（10 分钟）
在 `fall` 的 `steps` 列表末尾加第 5 个字典，字段照抄上面的。
**观察**：进度条 `0 / 4` 会自动变成 `0 / 5`，分数也按 5 题算 —— 因为你没有在任何地方硬编码 4。

## 5. 报错对照表

| 现象 | 大概率原因 | 去哪查 |
|---|---|---|
| 页面能开，但右侧任务面板空白 | 接口没通 | F12 → Network 看 `/api/scenarios` 是否 200 |
| 控制台 `Failed to fetch` | 服务没启动 / 不是通过 8000 端口访问 | 终端有没有 `Uvicorn running` |
| `422 Unprocessable Entity` | 提交的字段类型/长度不对 | `/docs` 里看该接口要求的格式 |
| 点选项没反应 | `selectChoice` 抛错 | F12 → Console 第一条红字 |
| 3D 区域一片空白 | WebGL 不可用 | 会自动出现「切换到 2D」提示 |
| 成绩不出现 | `POST /api/attempts` 失败 | F12 → Network 看这条的返回 |
| `Directory 'frontend' does not exist` | 启动目录不是项目根 | 在根目录执行 uvicorn |

## 6. 答辩时可以讲的三句话

1. **「前后端分离但同源部署」** —— 接口在 `/api/*`，页面由 FastAPI 的 StaticFiles 托管，因此不需要跨域配置；换部署平台只改启动命令。
2. **「答案在黑盒里」** —— 题库接口用 `public_scenario()` 剔除了 `correct` 和 `feedback`，判题在服务端，前端 F12 看不到答案；分数也由服务端重算，改前端改不了成绩。
3. **「外部依赖有退路」** —— AI 对话在没 Key、超时、返回异常时都会降级为角色预设回复，保证演示不会因为网络问题失败。
